# v0.92.0: 3D content

Ludra games can use any 3D model now: made in code, generated, or downloaded from a free pack. Skinned characters animate on the simulation clock, colliders can take any shape, and every asset can be read as text before it is used. It still runs through the same loop: `check`, `play`, `test`, `review` and real screenshots.

```bash
npx @ludra/cli inspect assets/knight.glb
```

## The idea, written down

README's "The idea" now lists the principles every feature is held to:
1. **Raw power, thin layer.** Three.js, Rapier, Web Audio, GLSL and Canvas are fully open to scripts.
2. **Starting points are source, not boxes.** Templates, blocks and examples are files to rewrite, not presets.
3. **Eyes.** Anything a human would check by looking, an agent can check from text or a real frame.
4. **Proof.** The engine, not the agent, does the searching.
5. **Taste.** `review` judges feel, not only completeness.
6. **Agent-shaped interface.** Plain JSON, short outputs, `--json` everywhere, and every error with a fix.
7. **Any asset, readable.** The engine describes models, images and sounds to the agent, so it never uses one blind.

This release delivers the last one. The roadmap below follows from the others.

## glTF models

`mesh.model` draws any `.glb` or `.gltf`, with its own materials, skins and textures. Draco and meshopt compressed files load too.

```json
{ "id": "knight", "components": {
  "transform": { "x": 0, "y": 0.9, "z": 0 },
  "body": { "type": "dynamic", "shape": "capsule", "width": 0.6, "height": 1.8 },
  "character": {},
  "mesh": { "model": "assets/knight.glb", "turn": { "y": 180 },
            "animations": { "idle": "Idle", "run": "Run", "jump": "Jump", "fall": "Fall" } }
} }
```

- **`fit`** sizes it to the entity:
  - `"height"` (the default) scales it evenly to the body's height, centres it and stands its lowest point on the bottom of the body;
  - `"box"` stretches it to width, height and depth;
  - `"none"` keeps its own metres.
- **`turn`** fixes its facing: most glTF characters face +z and Ludra's face -z, so `{ "y": 180 }`.
- **`scale` and `offset`** adjust it after fitting.
- A file that fails to load falls back to the mesh's shape, with one warning.

## Skeletal animation, deterministic

- **Clips follow how the entity moves.** `animations` maps the states `idle`, `walk`, `run`, `jump` and `fall` to clip names:
  - `walk` below 60% of `character.speed`, `run` above it;
  - `jump` while rising, played once and held;
  - `fall` on the way down.
  Any state can be left out.
- **Other clip sources:**
  - `animation` plays one clip forever (a windmill).
  - A script's `self.state.animation = "Wave"` overrides both.
  - `fade` crossfades between clips, and `animationSpeed` scales them.
- **On the simulation clock.** The renderer records which clip each entity plays once per simulation step. The pose is then a pure function of simulation time, so a screenshot of a frame shows exactly what live play shows.
- **Full control.** A render hook's `ctx.model` is `{ root, clips, mixer }`: find bones and materials, attach a sword to a hand, drive a clip yourself.

## `ludra inspect`: any asset as text

```
assets/knight.glb  glTF binary, 412.3 KB, made by Blender
  size        0.92 × 1.84 × 0.41 m (x × y × z)
  bounds      min (-0.46, 0.00, -0.20)  max (0.46, 1.84, 0.21)
  geometry    3 meshes, 5 primitives, 6120 vertices, 9874 triangles
  materials   Armor, Skin, Cloth
  textures    3 (3 images, 3 embedded)
  skins       Armature: 24 bones
  animations
    Idle                     2.00s 72 channels
    Run                      0.80s 72 channels

hint: Use it with "mesh": { "model": "assets/knight.glb", "animations": { "idle": "Idle", "run": "Run" } }
```

- **Models:** size in metres (node transforms applied), triangles, materials, textures, bones, every clip with its length, required extensions and external files. Its hints:
  - a ready `"mesh"` line with clips matched to idle/walk/run/jump/fall;
  - models exported in centimetres;
  - extensions that need decoding;
  - missing files.
- **Images:** width and height of PNG, JPEG, GIF, WebP and SVG, read from the header.
- **Sounds:** WAV duration, channels and sample rate; other audio by size.
- `--json` gives the raw object. The glTF reader has no dependencies.

## `ludra check` reads models

- `E_MODEL_INVALID`: the file isn't a readable glTF 2.0 model.
- `E_MODEL_FILE_MISSING`: a `.gltf`'s `.bin` or textures aren't next to it.
- `E_MODEL_ANIMATION`: a clip name the model doesn't have, with "did you mean" and the model's real clips.
- `W_MODEL_EXTENSION`: a required extension the renderer can't load, such as KTX2 textures.
- `E_INVALID_MODEL`: `mesh.model` isn't a `.glb` or `.gltf`.
- `E_ANIMATION_STATE`: an `animations` key that isn't a movement state.
- `E_MESH_DYNAMIC`: a `mesh` collider on a dynamic body.
- `E_MODEL_COLLIDER`: a collider that can't be built from its model.

A missing model file is `E_ASSET_MISSING`, as for images and sounds. Problems in a prefab's model are reported once, on the prefab.

## Colliders of any shape

- **`"shape": "mesh"`** collides with exact triangles: `points` `[[x, y, z], ...]` plus `triangles` `[[a, b, c], ...]`.
  - It is static or kinematic, for terrain, caves and level geometry.
  - Procedural terrain is just numbers: generate a heightmap grid in the scene or a script, and draw the same data in a render hook.
- **From a model.** `"body": { "shape": "mesh", "model": "" }` collides with the entity's own model, and `"convex"` takes the hull around it, for dynamic props. Point `body.model` at a simpler file to collide with fewer triangles than you draw.
  - The CLI reads the geometry while it loads the scene, fits it exactly like the drawn model, and writes plain points and triangles into the scene.
  - Headless tests and the browser get identical numbers, so physics stays deterministic.

## Moonlit Shrine

[`examples/moonlit-shrine`](https://github.com/ersingvn/ludra/tree/main/examples/moonlit-shrine) is a second 3D game. On a night lake, a hooded wanderer carries a lantern along floating stones toward a moon gate, gathering six shards of the moon. On the way:
- stepping stones;
- two pillars that rise and sink out of step;
- a torii that keeps a spirit lantern (the checkpoint);
- a stompable wisp guarding the bridge;
- a spirit spring that throws the wanderer up to the sanctum.

Everything is drawn in code: the water shader, the stars, the bloom chain, the paper lanterns. It has twelve tests, one per mechanic plus the pillars' timing window and the full route, and a clean `review --strict`.

## Upgrading

- `npm install @ludra/cli@^0.92.0`. Games simulate exactly as before: the 2D and 3D golden hashes are unchanged.
- Every new field has a default, so existing scenes need no changes.

## Next

The roadmap now follows the principles:
- **v0.93, proof at scale:** `ludra solve` searches inputs for a way to win (is the level beatable, the shortest route, how wide each timing window is). `ludra fuzz` runs thousands of random sessions to find softlocks, falls through the floor and crashes.
- **v0.94, sharper eyes and taste:** contact sheets, visual diffs between versions, a debug camera and map in 3D, readability checks, and a `game.md` of design intent that `review` measures the game against.
- **v0.95, humans in the loop:** record a person's session in `ludra dev`, let them mark moments, and turn any recording into a test.
- **v0.96, shipping:** a single-file web build for itch.io, touch and gamepad controls, performance budgets.
