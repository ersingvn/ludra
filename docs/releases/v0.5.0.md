# v0.5.0: scripting in TypeScript

**Scripting**: custom game logic in TypeScript, the Ludra equivalent of Unity's MonoBehaviours, while keeping its promise that the agent can prove the game works.

```ts
// scripts/locked-door.ts
import type { Script } from "@ludra/core";

export default {
  update({ self, world }) {
    const player = world.player();
    if (player?.state.hasKey && self.touches(player)) {
      world.emit("door-open");
      world.destroy(self);
    }
  },
} satisfies Script;
```

```json
"assert": ["events.door-open == 1", "player.state.hasKey == true"]
```

## Highlights

- **The `script` component** (`src`, `params`) has `start`, `update` and `touch` hooks. The script API:
  - `self`: position and velocity (read/write), `state`, `touches()`.
  - `world`: `get`, `all`, `player`, `spawn`, `destroy`, `kill`, `win`, `emit`, `score`, and a seeded `random()`.
  - `input`: `held`, `pressed`.
- **Testable**:
  - Per-entity `state` and custom events can be asserted (`<id>.state.<key>`, `events.<name>`).
  - A throwing script fails its test instead of crashing the run.
- **No build step**: Node's built-in type stripping runs the TypeScript directly.
- **`ludra check` catches script mistakes** with the line number and a caret:
  - syntax errors
  - runtime imports (only `import type` is allowed)
  - misspelled hooks
- **Errors name the file, entity, hook and frame.** In the browser they appear in an overlay instead of failing silently.
- **`ludra components script`** prints the full API.
- **New example**: `examples/key-quest`, with a jump pad, a key and a locked door, a chasing enemy and a time limit, all tested.
- **Engine fix**: variable jump height no longer cuts launches from jump pads; only the player's own jumps are shortened.
