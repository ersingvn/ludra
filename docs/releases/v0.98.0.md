# v0.98.0: Game systems

Until now an agent could make a tight arcade game in Ludra, and anything bigger meant writing its own enemy brains, inventory, dialogue and save files. This release puts those systems in the engine, so a game can have enemies that hunt, a story the player talks through, keys and locks, and a run that survives closing the tab, with no script. Like the rest of Ludra, all of it is deterministic, tested headlessly and checked by `review`.

## Enemies that hunt: `chase`

```json
"chase": { "speed": 110, "sight": 220, "memory": 2 }
```

A hunter waits, or patrols when it has a `patrol`. It **spots** its target when nothing solid is in between and hunts it **around walls**. When the target gets away it searches where it last saw it, then **gives up** and walks home.

- **Top-down** (gravity 0): it finds its way around every wall.
- **Side view**: it runs along the ground and stops at ledges, so a gap is a way to escape.
- **3D**: it walks the ground on x/z around whatever blocks it and turns to face where it goes. Defaults are in metres (10 m sight, 3.5 m/s). A kinematic sensor hunter with a `hazard` glides and kills on touch.
- It fires `spot` and `giveup` events. `review` counts a silent `spot` as unfinished: being seen without hearing it feels broken.
- `seeThroughWalls` gives it a nose or a radar. `target` can be any entity, not just the player.

## `world.findPath`: a way around walls

```ts
const path = world.findPath(self, target, { size: 20 });
```

`world.findPath` is the same pathfinding, for scripts: companions, units that go where they're sent, things that flee. It is a deterministic A* over the world's walls that keeps the walker's whole body clear of them, so the same world gives the same path on every machine. In 3D it walks the ground and steps over curbs.

## Story: items, locks, flags and dialogue

- **`item`**: a player touching it takes it into `world.items` and `pickup` fires. Items carry over to the next scene like score.
- **`lock`** on a solid opens for a player carrying what it `needs`, and fires `unlock`. Without the item it fires `locked`. A `goal` can `require` items too.
- **`world.flags`** holds the story so far: name → number, string or true/false.
- **`dialogue`** on an NPC or a sign: lines and choices that `set` flags and `give` or `take` items. `when` and `has` pick what the NPC says as the story moves on. The player presses action to talk, and up/down picks a choice.
- The engine draws a calm box. A game's own `drawUI` can draw it any way it likes from `world.talking`.
- **Testing**: tests walk up and talk with input scripts and assert `"flags.quest == \"hammer\""` or `"items.key >= 1"`. `ludra play` prints every line said and every choice made.
- `review` flags a dialogue no test talks to, and silent `talk` and `pickup` events.

## Saving the player's game, and menus

- **Saving.** `ludra dev` and `ludra build` save progress each time a scene other than the entry starts, and at checkpoints: score, lives, items and flags. Next visit, the entry scene offers **Continue / New game**.
- **For scripts.** `world.progress.save()`, `clear()`, `exists` and `continue()`. `"world": { "save": false }` opts a scene out.
- **Never saved.** Studio and recorded sessions.
- **Pause menu.** Esc, P, Start on a gamepad, the Ⅱ touch button or switching tabs pauses the game and shows Resume, Restart, Sound and Quit to title. The simulation clock stops while it's open. A script's `drawMenu` hook draws the menus in the game's own look.

## Also

- Recordings keep the items and flags a take started with, so a session in a later scene replays the same.
- In 3D, a hunter doesn't look before the first physics step, when Rapier's rays don't see anything yet.

## Upgrading

- **New built-in events.** `spot`, `giveup`, `pickup`, `unlock`, `locked`, `talk`, `say`, `choose`, `endtalk`, `saved` and `cleared` are now built in, so `world.emit` refuses those names. Rename a custom event of yours that used one.
- **Gamepad Start and the touch Ⅱ button now pause** instead of restarting. Restart is in the pause menu, and R still restarts.
- **Games played in the browser now save** (see above). Add `"world": { "save": false }` to a scene that should always start fresh.
