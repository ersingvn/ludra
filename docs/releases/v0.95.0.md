# v0.95.0: Humans in the loop

A search can prove a level can be beaten, and a review can say it isn't broken. Neither knows it was boring. Only a person does, and until now what they felt was lost the moment they closed the page.

This release brings a player's session back to the agent:
- every session in `ludra dev` is recorded;
- the player marks how a moment feels, while playing;
- `ludra feedback` adds up what players felt;
- `ludra replay` shows any moment again, and turns a run into a test.

```bash
npx @ludra/cli dev
npx @ludra/cli feedback
npx @ludra/cli replay . --test
```

## `ludra dev` records

Every session lands in `recordings/<session>.rec.json`. A session where no key was pressed leaves no file, and `--no-record` turns recording off.

While playing, a person presses `1` too hard, `2` boring, `3` confusing, `4` love this, or `N` for their own words. The game waits while they write.

## `ludra feedback`

What every recording adds up to, scene by scene: marks, deaths with their cause and place, where players stopped, and crashes.
- Moments within 64 px (4 m in 3D) of each other count as one place.
- Each line comes with the command that shows it.
- Those from an older version of the game are counted apart.

`--json` gives the same answer for a script.

## `ludra replay`

Plays a recording again from its inputs and says what became of each take, one run of one scene. A folder means its newest recording.

- **same:** it plays out as the player saw it.
- **changed:** the game changed since, and so did this run. It says in which 5 seconds the run left the original.
- **diverged:** the same game played differently, so determinism is broken.
- **gone:** the scene no longer loads.

Anything but `same` exits 1.

`--mark 1` with `--take` draws a contact sheet from 3 seconds before the mark to 1 second after, so an agent sees what the player saw when they pressed the key. `--sheet`, `--screenshot` and `--debug` work as in `ludra play`, on one take.

`--test` writes to `tests/recordings.test.json`: the takes that reached an end, or the last take if none did, or the one `--take` names.
- A take asserts `won`, `lost` or moving on, its score and its deaths.
- A take that wasn't finished also asserts where the player stopped, within 16 px (1 m in 3D).
- A take that crashed stays red until the bug is fixed.

## `ludra review` asks what players said

A new **Players** area reads the recordings of the game as it is now:
- **`R_NO_PLAYTEST`** (idea): nobody has played it yet.
- **`R_PLAYER_MARKS`** (idea): moments that bothered players.
- **`R_PLAYER_LOVED`** (idea): moments to keep.
- **`R_PLAYER_CRASH`** (issue, under proof): a player's run crashed.

Tests from recordings are a person's runs, not routes, so they don't count toward `R_FRAME_PERFECT`.

## Smaller things

- **`ludra play --from 3s`** starts a `--sheet` there instead of at the beginning.
- **`carry` and `recording`** on a test case: what the run starts with from the scene before, and the session it came from.

## Fixed

- **Tweens and 2D joints now give the same bits in every engine.** `sineInOut` and the other eases, the 2D joint helpers and the speed of players and of the breakout ball used `Math.cos`, `Math.sin`, `**` or `Math.hypot`, which engines may round differently. Chrome and Node really do: a run of Clockwork Keep, Moonlit Shrine or the 3D template split in the last bits. They now use `dmath` and plain arithmetic.
- **A test holds this in place.** It moves the result of every such `Math` function by a hair and requires each game's every frame to stay the same, so a new call in the simulation fails at once.

## Limits

A closing page's last request isn't sure to arrive, so a session can lose up to its last 2 seconds. Such a take counts as stopped and replays up to there.

Replay is checked between Node and Chromium: frame by frame on all 10 games and templates, in Chrome 156 and Edge 156 against Node 24 on Windows x64. Firefox and Safari haven't been tried: if a recording from one of them doesn't play the same, `replay` says `diverged`.

## Upgrading

- `npm install @ludra/cli@^0.95.0`.
- **v0.93 and v0.94 weren't published on their own**, so this is the first npm release with `ludra solve`, `ludra fuzz`, `ludra diff`, `play --sheet` and `game.md`. Their notes are in [v0.93.0](v0.93.0.md) and [v0.94.0](v0.94.0.md).
- **Tweened motion can move by a last digit.** Nothing to do unless a test of yours compares exact values from a tween.
- **`ludra dev` now records by default.** A `recordings/` folder appears in the project once someone plays. Use `--no-record` to turn it off.
- **`review` asks more of existing games.** A game nobody has played gets the idea `R_NO_PLAYTEST`, and a recorded crash on the current version is an issue, so `review --strict` can start failing on it.
