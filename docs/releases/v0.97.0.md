# v0.97.0: Ludra Studio

An agent can make a game in minutes, but until now a person could only see the result when it was done. Ludra Studio is a desktop app to watch it happen: the game runs in the window, and each change the agent makes shows up in place, with its diff, while the game keeps going.

```bash
npm install -g @ludra/cli @ludra/studio
ludra studio my-game
```

Then run your agent (Claude Code or any other) in `my-game` and watch.

## What you see

- **The game, live.** It plays in the middle of the window. You can pause it, step frame by frame, restart it or pick a scene. You can also play it yourself.
- **Hot reload that keeps your place.** When the agent changes a scene, a prefab, a script or an asset that the running scene uses, Studio rebuilds the world and replays the inputs played so far, up to the same frame. The game doesn't restart: "state kept at 41.5 s". A change that doesn't pass `check` is rejected, and the old version keeps running.
- **Activity.** Every file the agent touches, as it happens, with a syntax-colored diff and the hot reload's result.
- **Hierarchy and Inspector.** The scene's entities with search and icons, and the selected one's components with live values. Click an entity in the game to select it (2D).
- **Problems, Tests, Review, Console.** `check` runs on its own after each change, so Problems is always current. `test` and `review` run with one click.
- **A native app.** Menus, Open project and recent projects, a remembered window size and shortcuts: F5 play/pause, F10 step, Ctrl+R restart, Ctrl+Shift+C check, Ctrl+Shift+T test.

## `ludra dev --studio`

Studio drives an ordinary `ludra dev` server with `--studio`, which adds `/__ludra/project`, `/__ludra/events` (file changes as server-sent events) and `/__ludra/run` (check, test and review as JSON), and game pages that hot-reload in place. The whole protocol is in [`docs/studio.md`](https://github.com/ersingvn/ludra/blob/main/docs/studio.md), so other tools can use it too.

The studio endpoints answer only a local host and, when `LUDRA_STUDIO_TOKEN` is set, only requests that carry it. Studio makes a random token for each game it opens, so a web page open in your browser can't read your project through them.

## Games on GPUs that drop WebGL

Some GPUs give a page a WebGL context and lose it right away. A scene with a `postfx` shader then showed a white frame. Now a lost context counts as no WebGL: the game plays on without its shader, as it already did where WebGL is missing, and the page doesn't ask again, so the browser doesn't fall back to drawing everything in software.

## Upgrading

- Nothing to change in your games.
- `@ludra/studio` is a separate package because it brings Electron. `@ludra/cli` doesn't depend on it: `ludra studio` finds it when it's installed, and otherwise says how to install it.
