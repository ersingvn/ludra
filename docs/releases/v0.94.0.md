# v0.94.0: Sharper eyes and taste

We built the same game twice, once with Ludra and once without. The Ludra game passed its checks, and the person who played both still found the other one more creative and more beautiful. Checks had caught what was broken and said nothing about what was dull.

This release makes an agent look harder at its own work, and decide what a game should look like before drawing any of it:
- see a whole run at once;
- see exactly what a change changed;
- find what the player can't read;
- write down a look, and be held to it.

```bash
npx @ludra/cli play . --sheet 0.5s
npx @ludra/cli diff before/ after/
```

## `ludra play --sheet`

One PNG of the whole run: a frame every interval and the last, each with its time. An agent reads a run in one image instead of opening a screenshot at a time.

## `ludra diff`

What changed between two screenshots, or two folders of them matched by file name.

```bash
ludra diff before.png after.png --out diffs --threshold 24
```

`--json` gives the same answer for a script.

## `ludra play --camera`

For 3D scenes, draws the frames from somewhere other than the game's camera, with `--screenshot` or `--sheet`:
- `--camera map`: the whole level from above.
- `--camera x,y,z@x,y,z`: from a point, looking at a point.
- `--camera x,y,z@player`: looking at an entity.

## `ludra review` asks whether you can read it

A new **Readable** area draws moments along the winning route with and without the player, hazards, goal and collectibles, then measures each against what is behind it. `R_LOW_CONTRAST` names what blends in, the moment, and the contrast it measured.

The measure can differ a little by the order things are hidden in, so treat a number near the limit as a reason to look at the frame.

## `game.md`: a look decided first

No tool can tell a good look from a dull one. So a game writes down what it means to be, before its first asset: a promise, a style, its type and its palette. Every template and example now has a `game.md`, and their guides ask for it before any art.

`review` then holds the game to what can be measured:
- **`R_NO_DIRECTION`, `R_THIN_DIRECTION`** (issues): no `game.md`, or a part left undecided.
- **`R_OFF_PALETTE`** (idea): art that has left the palette.
- **`R_REPEATED_TILES`** (issue): one tile image filling thick blocks. It counts from the scene, because measuring repetition from frames failed on real games.
- **`R_ALIKE_LEVELS`** (idea): levels whose frames share their colors.

A clean review now says what it means: the game isn't broken, not that it's good. It sends you back to the frames.

## Tools for a tighter look

- **`"pixelated": true`** on `window` draws at low resolution and shows it at a whole multiple, with hard pixels.
- **`ctx.pixelText`** writes sharp 5×7 capitals with Turkish and Latin marks. Its `locale` option gets a language's capitals right (with `"tr"`, i becomes İ and ı becomes I). A game using it no longer gets the system font idea.
- **`"variants"`** on a tiled sprite or a tilemap legend entry mixes in more cells of the same size, so the grid doesn't show.

## Fixed

- **A game plays on without WebGL.** A finishing shader is optional, so a browser without WebGL now shows the game without it, with a console warning, instead of covering the game with an error. A shader that fails to compile is still an error.

## Upgrading

- `npm install @ludra/cli@^0.94.0`.
- **`review` asks more of existing games.** A game without a `game.md` gets `R_NO_DIRECTION`, and big blocks of one tile get `R_REPEATED_TILES`, so `review --strict` can start failing on a game that passed before. Add a `game.md`, and `"variants"` on the tiles.
