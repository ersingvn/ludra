# v0.96.0: Shipping

A game that only runs in `ludra dev` hasn't reached anyone. This release takes it to where players are: one file for itch.io or any web host, played with a keyboard, a gamepad or a phone's screen, with `review` saying what would make it heavy or slow there.

```bash
npx @ludra/cli build
npx @ludra/cli review
```

## `ludra build`

```
✓ Built Slime Valley: 1 scene, 2 scripts, 8 assets
  build/index.html  395 KB   one file: open it, or put it on any web host
  build/slime-valley-web.zip  100 KB   for itch.io: upload it as an HTML game
```

`build/index.html` is the whole game: engine, every scene, scripts, images, sounds, fonts and models. It plays from a double click (`file://`), any web host or an itch.io page.

- **No bundler.** Ludra puts each module in the page as it is, type-stripped, and links them with an import map, so it stays free of dependencies.
- **Only what the game runs.** An arcade game is a few hundred KB. Rapier (about 3 MB) and Three.js (about 2 MB) come only with games that use them, and only the Rapier a game uses.
- **Never a broken build.** It refuses what `ludra check` refuses, scripts included, and says why.
- **A shipped game.** The page fills its window and keeps the game's shape (pixel art scales by whole steps), backquote no longer opens the debug view, and nothing in the file names the machine that built it.
- `--out` picks the folder, `--json` gives the same answer for a script.

## Gamepads and touch

- **Gamepads** play in the standard layout: the left stick or the d-pad moves, A jumps, the other face buttons are `action`, Start restarts and Back mutes.
- **Touch screens** get buttons on the first touch, for the actions this game uses: what its player components need, and what its scripts read (`input.held("action")`). Movement sits under the left thumb, where a finger can slide round and press diagonals; jump and action under the right; sound and restart in a corner.
- **`view.touch`** tells a draw hook the buttons are showing, so a game's own interface can say "tap" instead of naming keys. Every template's and example's HUD now drops "M sound · R restart" then, as the default HUD does.

Both work in `ludra dev` too, and go into recordings like keys: a session played with a gamepad or on a touch screen replays and becomes a test the same way. A build doesn't record.

## `ludra review` asks if it will ship

A new **Shipping** area:
- **`R_BIG_BUILD`**: the zip is over 10 MB (an idea) or 50 MB (an issue).
- **`R_HUGE_IMAGE`**: an image over 4096 px on a side. An issue for a 3D texture, which many phones can't load; an idea for a 2D image.
- **`R_HEAVY_ASSET`** (idea): one file over 8 MB, usually an uncompressed WAV.
- **`R_HEAVY_MODEL`**: a 3D scene's models draw over 1M triangles (an idea) or 4M (an issue), counted once per entity showing one.
- **`R_MANY_ENTITIES`**: over 2000 entities alive at once in the tests' runs (an idea), or 6000 (an issue).
- **`R_SLOW_STEP`** (idea): a step takes over 3 ms on this machine.

What can fail `--strict` is counted, not timed, so a busy machine reviews a game the same as an idle one.

## For engine users

- **`startGame`** takes `assetUrl` (where each asset path loads from), `loadScript`, `actions`, `touch: false` and `debugKey: false`.
- **`SoundPlayer`** takes a function from path to URL as well as a prefix.
- **The 3D renderer** loads through a `LoadingManager`, so a `.gltf`'s own `.bin` and textures are found wherever assets live.
- **`actionsUsed`** is exported from `@ludra/core`.

## Limits

- Draco-compressed models don't load in a build (the decoder is a separate file), and Google fonts need the internet. Others use a fallback font offline.
- Render hooks must name three addons with a literal, `addon("postprocessing/RenderPass.js")`, for the build to find them. It says when one doesn't.
- Touch controls are checked in Chrome's phone emulation, with real and synthetic touches. They haven't been tried on a real iPhone or Android phone yet.

## Upgrading

- `npm install @ludra/cli@^0.96.0`.
- **`build/` appears in a project** once you build. New projects ignore it in git; add `build/` to an existing project's `.gitignore`.
- **A draw hook's `view` has a new field, `touch`.** Nothing to do, unless code of yours builds a `view` object by hand for a draw hook's type.
- **On a touch screen, buttons now cover the bottom corners of the page.** Keep what players must see out of the bottom 150 px at the sides, or check `view.touch` and move it.
