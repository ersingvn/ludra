# v0.99.0: Studio as an editor

Ludra Studio (v0.97) let a person watch an agent make a game. This release lets the person **work on it too**, in the same scene and at the same time: select a thing in the game and drag it, change a value in the inspector, drop a prefab or a block into the level, delete, undo. Every edit is written to the scene's JSON, the same files the agent edits, so the agent sees what the person did, and Activity shows who did what.

Three rules hold for every edit:

- **The files are the truth.** Studio keeps no copy of the scene. An edit is a change to a file, and the game shows it through the same hot reload as an agent's change.
- **Never lose the agent's work.** An edit names the version of the file it was made against. If the agent wrote the file since, the edit is refused. A tool in the game view then makes it again on the new version, touching only what the person changed; the inspector reads the file again and shows it as it is now.
- **Never write a broken scene.** The server runs the same validation as `ludra check` on the result and refuses an edit that adds an error, with the diagnostic and its `fix`.

## Edit in the game view

Pause the game (or turn on the pick tool) and the viewport becomes an editor, in 2D:

- **Click** selects, **drag** moves (whole pixels, or snapped to the grid). **Shift** keeps to one axis, **Alt+drag** duplicates.
- **Delete** removes, **Ctrl+D** duplicates, **Ctrl+Z / Ctrl+Y** undo and redo, **F** frames the selection, **G** toggles the grid.
- The **palette** lists the project's prefabs and the block library. Pick one, and a ghost follows the pointer; a click places it (Shift+click keeps placing).
- The **hierarchy** renames (F2), duplicates, frames and deletes from a right-click menu, and reorders by dragging.

Dragging is presentation only: the world doesn't change until the edit lands in the file, so the engine stays deterministic.

## An editable inspector

- Every field of the selected entity's components, from the component schema: the file's value, the default as a placeholder, and the **live value** beside it when the game has moved away from the file.
- Enter writes, Esc reverts, and dragging a number field's name scrubs it, like Unity.
- **Prefabs**: values from the prefab show in italics, overrides with a bar, and ↺ takes one back to the prefab's.
- Add and remove components, and rename an entity by clicking its id.
- Entities the scene file doesn't hold (a tilemap's cells, things spawned while playing) are read-only, with why.

## Edits are one-line diffs

```diff
         "transform": {
-          "x": 320,
+          "x": 352,
           "y": 400
         },
```

A write keeps the agent's formatting byte for byte: key order, indentation, line endings, objects written on one line, and how numbers were spelled. Only the values that changed show up in the diff.

## For tools: the edit API

`ludra dev --studio` gains `GET /__ludra/file`, `POST /__ludra/edit` (`set`, `add`, `remove` and `scene` edits, all applied together or not at all), `/__ludra/undo` and `/__ludra/redo`. The `change` event says `by: "studio"` or `by: "files"`, and `/__ludra/project` lists prefabs, blocks and the component schema. See [`docs/studio.md`](https://github.com/ersingvn/ludra/blob/main/docs/studio.md).

## `ludra solve` on long levels

On long levels the search used to give up (about 100 columns in four minutes), and `fuzz` then skipped its softlock checks. When exploring stops getting closer, a **beam** now keeps the 100 situations nearest the goal and moves them forward together, and a jump only counts if pressing it 6 frames late also lands, the slack a person needs. Levels that weren't solved in 90 seconds now solve in 10 to 22. The output is the same, with `strategy: "beam"` in the result.
